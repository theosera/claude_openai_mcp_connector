# correction-layering — 訂正の第一手は分類であって、書くことではない

**腐った値を消して置き換えると、腐っていたという事実が消える。** 残った文書は
「最初から正しかった」と区別が付かない。ただし**すべてを重ねると文書は単調増加する** —
どちらに倒すかは、腐り方の分類が決める。

## 規則

1. **先に腐り方を 3 分類する** (GD-DECAY-KINDS):
   - **① as-of 付きの値が古くなった** → **差し替え** (削除が正。重ねると履歴が無駄に伸びる)
   - **② 有効範囲なしで偽になった** → **消さずに重ねる** (GD-KEEP-CORRECTED の対象はここだけ)
   - **③ 実行済みの命令** → **完了記録に書き換える**
2. **保持の射程は「いったん正典になった値」だけ。** staged のまま着地しなかった下書きは
   対象外 — 広げると全 staged plan が保持対象になり、規則が使えなくなる。
3. **旧値の出現は 2 種類あり、潰してよいのは片方だけ**: 現役の参照 (存在しない対象を指す)
   は潰す / 訂正・リネームの**記録**は残す — **記録は旧値を含んでいなければ記録にならない**。
   「旧名を grep して全部潰す」は規則として誤り (却下済み)。
4. **「同じ事実を 2 箇所に書かない」を根拠に訂正記録を消さない。** 新値が述べるのは現在、
   旧値が述べるのは「かつてそう書いていた」という**別の事実**。
5. **訂正は被覆を数えてから重ねる。** 同じ主張が何箇所に生きているかを grep で数え、
   各出現を (a) 同時に訂正するか (b) 未被覆として path:line を列挙する。訂正 1 箇所・主張
   3 箇所は被覆 1/3 であり、「訂正済み」ではない。
6. **主張を書くときは、先に置き場所を 1 つ決める。** 複数に書いてから片付けるのは、
   片付いたかどうかが原理的に確かめられない。
7. **訂正自身が同じ形で誤りうる。** 訂正にも元の主張と同じ検査 (内訳の列挙・単位・分母) を課す。
8. **消した数は数えられない** (silent erasure)。走査で得られる訂正保持の件数は**下限**であり、
   0 件を「規則不要」の証拠にしない (→ `measurement-scope` の下限規律)。

## 事故録 (すべて実測)

- **否定済み主張が 3 箇所・訂正 0 箇所のまま、87,707 B / 1,174 行の文書が受け渡し直前まで
  進んだ** (前 G4 セッション実測)。書いた本人も読んだ人も渡そうとするまで気づかなかった —
  被覆を数えない訂正は、被覆率を測れない。
- **M-20 の標本数を 7 → 8 → 10 と二段階で外した** (G4 台帳 A-2)。第 1 訂正「8」自体が
  同じ形 (数え落とし) で不足しており、**3 者が同じ「8」を書いて中身が 3 通り違った**。
  → 標本は内訳でしか書かない。
- **「再測定待ち」を訂正として重ねようとした** — 一度も正典になっていない値だったので
  差し替えが正 (射程の逆適用。指摘は G3、2026-08-17)。
- **初適用 (2026-08-17)**: staged 2 plan にだけあった説明を、着地 0 件を実測確認した上で
  直接書き直した。着地していれば重ねていた。
- **分類①の実地 (2026-08-18)**: P6 で「タグ列は未取得」の注記を**意図的に消し**、一般則だけ
  残した — as-of 付きの注記は差し替えてよい側。
- **同じ主張が 4 つの正典に散り、別々のレビューで 1 つずつ見つかった** (js-yaml 記述,
  2026-08-10)。「全部直した」と言える瞬間が無い — 規則 6 の根拠。
- **報告の失敗は 4 種類** (GD-REPORT-KINDS: 測らず断定 / 要約が枝を落とす / 正しく測って
  違う名前で報告 / インフラ失敗)。どれも正しい報告と見分けが付かない — **執行するのは常に
  次の読み手**である。

## アンチパターン

- 分類せずに反射で重ねる (① に重ねる) / 反射で消す (② を消す)
- 「訂正した」宣言だけで旧値の全出現を数えない
- 台帳・訂正記録の件数を悉皆として報告する (下限と宣言する)
