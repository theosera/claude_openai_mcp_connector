# measurement-scope — 主張の射程 = 測定の射程

**測定は実行したのに、測定範囲が主張の範囲より狭い** — これが最も重い失敗型だった。
測っていない断定より発見が難しい。報告が正しい報告と見分けが付かないからである。

## 規則

1. **主張を書く前に、その主張が要求する測定範囲を言う。** 「byte 一致」は全 byte を
   比較した後にしか書けない。先頭 N 文字の比較が支えるのは「先頭 N 文字は一致」まで。
2. **分母を先に数え、報告に分母を書く。** 分子だけの報告は悉皆に見える切り取りになる。
3. **空集合・0 件・全緑には、先に「検査に到達したか」を問う。** 0 は「無かった」と
   「見に行けていない」を区別しない。到達の証拠 (読んだファイル数、踏んだ分岐、実行された
   比較の回数) を主張と一緒に出す。
4. **ガードの検証は「外して赤」を実測してから。** 緑は「壊れていない」であって
   「守っている」ではない。赤は**そのガードの不在を名指しできる**こと (互いに素な赤)。
   変異がガードに**届いている**ことまで確認する (届かない変異は何も証明しない)。
5. **単位を宣言する** (chars / bytes / code points / UTF-16 units / 行)。単位の混在は
   文書ごとに違う差を作り、「systematic なずれ」という誤った補正を誘発する。
6. **構造は推測せず、現物を 1 度 dump してから読む。** 存在しないキーへのアクセスは
   静かに 0 / undefined を返し、規則 3 の形 (vacuous) に合流する。
7. **標本が変数に届いているかを問う。** 変異が分岐に届かないのと同族 — **変数を跨がない
   標本からは、その変数について結論を出せない**。切り分けは「同じ道具で 2 回」ではなく
   **別の道具 (別言語・別実装) で同じ切り出しを測る**。
8. **件数は下限と宣言し、精度を一様に見せない。** 「15 件」は 15 件**見つけた**という意味
   しかない (捕まらなかったものは台帳に現れない)。捕捉率は「4 件着地して 3 件止めた」で
   あって「7 件中 3 件」ではない。項目ごとに精度が違うなら (秒まで実測 / 未測定)、
   そう書く。

## 事故録 (すべて実測 / 2026-08-16〜19 の 3 セッション協働)

- **`cut -c1-62` で「byte 一致」と報告** — 実際は 3 例中 1 例だけ一致。他 2 例は
  199 / 477 文字目以降が不一致 (285→331 / 755→673 chars の改稿を見逃した)。
  測定は実行されており、範囲だけが狭かった。
- **存在しないフィールドを推測で読んだ** — 合計が常に 0 (vacuous)、正しい値は入れ子の
  1 段下にあった。同型の誤りを同じ日に繰り返した。dump して解決。
- **空配列を「leak 0 = OK」と判定しかけた** — 0 件なのは漏れが無いからではなく、
  経路に到達していないからだった。
- **逆検証で変異が届かず緑 ×2** — 定数を 0 にしたら assert の両辺が同時に 0 /
  変異が読む値を呼び出しがもう要求していない。届く変異に書き直して赤を確認。
  2 境界を 1 テストに同居させると赤がどちらか名指しできないので分割した。
- **走査の枝刈りを「常に真」に潰しても全テスト緑** — assert が末端の open 数だけを見て、
  枝刈り分岐には一度も届いていなかった。ディレクトリ列挙の回数も数えて初めて赤になった。
- **検査が毎回きちんと FAIL しながら、比較の手前で throw していた** — FAIL したときも
  「検査した結果か、検査に到達しなかった結果か」を問う。
- **「systematic に +2」— 3 標本すべてが差を動かす変数を跨いでいなかった** — 実際は
  UTF-16 code unit と code point の差で、**文書ごとに +2 / +3 / +46**。別言語で同じ
  切り出しを測って切り分けた (規則 5 と 7 の複合事例)。
- **「archive は commit している」という前提が偽** — 当該行に一度も到達していなかった
  (変数未解決)。コードの読解は正しく、実行だけが無かった。動作の主張は到達の実測とセット。
- **表の 400 字打ち切りが「判定の書かれた第 3 列」を落としかけた** — セルに分割し、
  列数 = 3 を先に assert してから読む形で着地前に捕捉。
- **事故台帳自身も下限である** — 台帳 2 通が末尾に自己限界 (数え落とし非排除 / 捕捉率
  未測定 / 精度の非一様) を明記した。**一覧だけ抜くと「これで全部」と読まれる** —
  下限宣言は一覧とセットで運ぶ (規則 8 の出所)。
- **空 diff をレビューして「指摘なし」** になりかけた — 走らせる前に入力が空でないことを
  確かめる。

## アンチパターン

- 「テスト N 件緑」を逆検証の代わりに数える (N がいくつでも、新しい分岐を踏んでいなければ同じ)
- 先頭一致・部分一致で全量一致を主張する
- 総数だけの報告 (→ `handoff-block-integrity` の「総数でなく列挙」)
- 台帳・スキャン結果の件数を悉皆として引用する
