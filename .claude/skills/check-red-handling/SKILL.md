# check-red-handling — 機械の赤は人を呼ぶ合図であって、判定ではない

検査の役割分担は **機械 = 検出 / 人 = 妥当性の判定**。機械の出力は「**ここを人が読め**」
という指示であり、それ自体は却下でも承認でもない。**この段を飛ばした却下は、検査の名を
借りた無判定である。**

## 規則

1. **赤が出たら、まず現物 (diff・該当行) を読む。** 読む前に破棄・却下を決めない。
   検査は「どこを見るか」を教えるだけで、「どうするか」は言っていない。
2. **赤の原因は 3 種を見分ける**: (i) 本物の誤り (ii) **無害な差** (iii) **検査自身の偽陽性**。
   (iii) は実測された族がある — 素朴な計数 (`@@` の `-` を 17 と数えた。真は 3) /
   個数検査は両方向に壊れる (`**` を code span 込みで数えて 47 = 奇数と誤読) /
   自己言及 (実体参照の検査は、検査自身の記述に反応する — **ブロック内で数える**)。
3. **却下は無料ではない。** 却下 1 回 = 転記 1 回増 = 転記誤りの期待値上昇。
   「byte 一致でなければ却下」は、**防ごうとしているものを自分で増やす**。
   却下・削除・やり直しを選ぶときは、**それが強制する作業量まで込みで判定する**。
4. **byte 契約が効く場所は「宣言した対象そのもの」だけ。** 受け手が sha256 で検証する
   ブロックでは byte 一致が契約であり、そこでは復元が正しい (末尾改行を落としたら戻す)。
   **検査が出した差分は契約ではない。** 契約は「削除なし・挿入 2 箇所」という**主張**であり、
   差が出たときに要るのは**主張を実際に合わせ直すか、直すかの判断** — 破棄は最後の選択肢。
5. **差の申告は破棄に勝る。** 宣言 6 箇所 / 実際 8 箇所 → 破棄せず差を申告し、
   **承認の対象を実際に合わせる**のが正しい対応 (実測で対比あり: 同じ形に申告で応じた側が
   正しく、却下で応じた側が誤った)。
6. **判定条件を二値の崖にしない。** 「届かなければ捨てる」は、実測 79.4% が中間に落ちて
   判定不能になった。**中間帯に落ちたときの扱いを条件と一緒に先に書く。**
7. **正しい行為に誤った根拠が付いていたら、行為を維持し、根拠だけ訂正する。**
   (再 plan は正当・挙げた理由が誤り、という形は実在する。)
8. **得た教訓を、いま作っている成果物に足さない。** 足せば手写しがもう 1 回増え、
   教訓が禁じる形をその場で踏む。**着地させてから、別便で足す。**
9. **赤を迂回するのも「読まなかった」である。** 規則 1 が禁じるのは**赤を根拠にした破棄**
   だが、**赤を根拠にせず先へ進むこと**も同じ穴の裏面である。失敗したコマンドは、迂回する
   障害ではなく**読むべき証拠**である。**迂回した赤は、後から「そもそも観測できなかった」
   という一般論に化ける** — 実際には観測手段が自分の出力に出ていて、読まなかっただけ、
   という形になる。**一般論としては正しい限界の主張が、その回に限って偽になる**ので、
   限界を述べる前に自分の出力を読み直す。

## 事故録 (実測 / 2026-08-18〜19 の 3 セッション協働 + 2026-09-02 の追補)

- **無害な 1 文字差で plan を破棄し、24,663 code point を写し直した** (2026-08-19 未明の実測)。
  差は `**…である**。` ⇄ `**…**である。` — `**` は 4 個で対応も閉じ、意味も構造も同じ。
  **diff を読まずに**、検査②の赤が出た瞬間に破棄を決めていた。しかも「`-` 行 0 本を
  要求するな」という既存規則を、**名前を変えて (「宣言と 1 byte でも違えば破棄」) 復活**
  させていた。捕まえたのは機械でも本人でもなく**ユーザ**。
- **2 回目の転記がたまたま清潔だったのは、結果であって設計ではない。**
- **G3 台帳の型 D (検査そのものの誤り) は 15 件中 3 件** — 検査を足したことで**新しく
  生まれた**失敗。検査は追加すれば安全になるのではなく、検査自身が偽陽性の供給源になる。
- 同じ turn 内の対照実験: G4 は「宣言 6 / 実際 8」を申告で処理 (⭕)、G3 は「宣言差 1 字」を
  却下で処理 (⛔)。**却下した側は直前に、申告した側の対応を「検査が機能している」と
  評価していた。**
- **`git fetch` が `fatal: couldn't find remote ref …` を返し、sha 直指定で迂回した**
  (2026-09-02 / 別セッションの自己申告)。この赤は「マージ後に head ブランチが削除された」の
  署名そのもので、**自分の基点が古いことを告げていた**。後に「その席は自分の基点の古さを
  観測できない」と一般化されかけたが、**一般論としては正しくても、この回に限っては当たらない** —
  観測手段は自分の出力に 1 本出ていた (規則 9 の出所)。

## アンチパターン

- 「検査が赤を出したので破棄しました」(検査は破棄を指示していない)
- 偽陽性が出た検査をその場で捨てる (検査の修正対象と、検査対象の修正を混同する)
- 教訓の即時反映 (規則 8 — 3 回目の手写しを生む)
- 赤が出た呼び出しを別経路で置き換えて先へ進む (規則 9 — 「エラーは出たが目的は果たせた」は
  赤を読んだことにならない)
