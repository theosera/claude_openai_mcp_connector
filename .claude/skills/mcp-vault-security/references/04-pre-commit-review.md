## pre-commit レビューの発火 (CLAUDE.md 発火表の詳細)

`CLAUDE.md` は「`fs` write 経路 / write surface の gate / 出力の封じ込め / 送り先の認可を触ったら
**ローカル commit 後・push 前**に **(a) `/claude-security` の change scan、無ければ (b) `/security-review`**」
と定める。`CLAUDE.md` の「回す前に基点 2 行」で対象の commit 範囲と未 commit 差分を確認し、所見の対象が変更ファイル集合に含まれることを照合する。レビューは push 直前の最後の操作とする。⚠️ **発火点は 2026-09-17 に「commit 前」から動いた** —
(a) は commit 済みの差分しか読まないので「commit 前」は定義上いつも空 diff だった。節名の pre-commit は
残す (名前であって規則ではない — ポインタを持つ `CLAUDE.md` 側と対で変えるまで動かさない)。

**(a) と (b) は同じものの強弱ではなく、層が違う** (公式 docs も別レイヤとして並べている):

|            | (a) `/claude-security` (plugin)                                     | (b) `/security-review` |
| ---------- | ------------------------------------------------------------------- | ---------------------- |
| 走り方     | 多エージェント。構成把握 → 脅威モデル → 探索                        | **単一パス**           |
| 指摘の扱い | **別エージェントが全件を独立検証**し、通ったものだけ残す            | そのまま出る           |
| 対象       | リポ全体 / branch / PR / 単一コミット (**commit 済みの差分**) を選べる                       | **セッションの cwd** の diff (範囲指定可) |
| 前提       | Claude Code v2.1.154+ / 有料プラン / `python3` 3.9.6+ / plugin 導入・**`disable-model-invocation` = 人が打つ** | 組込み                 |

→ **(b) を残す理由は前提未達の環境が実在するからで、同等だからではない。**

**実測 (2026-08-11 JST)**: `atomicWrite.ts` を足した際、temp を既定 mode で作ってから `chmod`
していたため **`0600` のノートが書き込み中だけ `0644` で存在**した。**CI 7 step 全緑・逆検証
4 ガード分パスの後で、(b) だけがこれを出した。**

⚠️ **それでも逆検証の代わりにはならない。** 同じ PR で、mtime を戻す cache テストが**ガード無しでも
緑**だった件は**レビューでは出ず、逆検証だけが**出した。**レビュー = 書かなかったガード /
逆検証 = 書いたガードが効くか。**

⚠️ **走らせる前に diff が空でないことを確かめる。** **実測**: `origin/HEAD` 未設定で
`git diff origin/HEAD...` が全部エラーになり、**空 diff をレビューして「指摘なし」になる寸前**
だった (`git remote set-head origin main` で復旧)。cache テストが vacuous に緑だったのと**同じ
失敗モード** — 検査した結果か、**検査に到達しなかった結果か**。

⚠️ **どちらの分岐も、外部レビューの代わりにはならない。** 2026-08-11 に (b) を通した PR へ、
外部レビューが **P2 を 2 件**足した (write 計画の parse 縮退 / 所有者を戻せないまま rename)。
**どちらも「書かなかったガード」で、(b) が拾える形だったが拾わなかった。**
