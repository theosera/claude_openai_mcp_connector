# claim-freshness — as-of の無い提示は提示ではない

進捗ノート・作業メモ・受け渡された写しは、**外部状態のキャッシュ**である。
キャッシュを現在の状態として提示した瞬間から、提示は黙って腐りはじめる。
**as-of だけが、提示を鮮度の窓の外まで生き延びさせる。**

## 規則

1. **提示には必ず as-of を付ける** (`YYYY-MM-DD HH:MM JST` — 日付を省かない)。分岐は 2 つ:
   **(a)** 外部 (GitHub / vault) を再取得する → as-of は**取得時刻**。
   **(b)** 取得しない → as-of は**ノートの時刻**とし、**「未確認」と添える**。
   「必ず取得せよ」にはしない — 取得できない状況で守れない規約は規約ごと無視される。
2. **as-of の時刻は本文より先に取る。** 窓は「作業していない間」に開く — 6 時間 10 分の
   空白は、`date` を先に実行していたから検出できた。体感の時刻で as-of を書かない。
3. **突き合わせ窓の下限は、得られた候補のうち最も早いものを採る** (優先順位で 1 つ選ばない)。
   下限は早い側に外れる分には安全 (窓が広がるだけ)、遅い側に外れるとその間の変化を丸ごと
   見落とす。
4. **mtime を下限に使わない。** checkout・コピー・rsync で動くので、内容が古いまま mtime
   だけ新しくなる。下限は**内容の更新に結びついた値**でなければならない。
5. **渡された写しを読まない。** 正典 (main の実ファイル / vault の現物) を再取得する。
   行番号つきの参照はキャッシュとして扱う (→ `anchor-decay`)。
6. **測定対象は測定中にも成長する。** 測定値自体に時刻を付ける。失われた時点の値は
   原理的に再構成できないことがある — 「取れなかった」を取れたかのように埋めない。
7. **as-of 付きで書いた値は「古くなる」だけで「誤りにならない」。** 有効範囲を持たない値
   だけが偽に転じ、訂正の重ね書きを要求する。**書く時点で as-of を付けることは、将来の
   訂正 overlay を先回りで不要にする** (→ `correction-layering` の分類①)。
8. **記録は行為に追随して初めて鮮度を持つ。** 「起票した」と「記録が起票を反映した」は別 —
   行為の直前に書いた「未実施」は、行為の直後から偽として読まれる。

## 事故録 (すべて実測)

- **担当表を 10:32 JST に提示 → 90 分後の 12:02 に該当 PR がマージ → 提示が陳腐化**
  (2026-08-10)。メモは正しく、読まれ、判断も正しかった — 誤りは as-of を落としたことだけ。
  as-of さえあれば、あの提示は今も正しい。
- **サーバ管理タイムスタンプの差 (83 分 / 2.4 分 / 38 秒) から「差の大小が書込経路を
  言い当てる」と読んだ** — 観測は正しく、推論が広すぎた。残るのは「早い側へずれうるので
  下限として安全、新しさの証明には使えない」の一点だけ。
- **セッションアーカイブは 6 分で +24,336 chars 成長した** (測定中の実測、2026-08-17)。
  さらにこの種のノートは**毎ターン全文再生成で置換される** — 引用には「何時時点の版か」を
  必ず添える。
- **as-of 付きの値は訂正規則を発火させなかった** — 「古くなっただけで誤りになっていない」
  (2026-08-18 実測)。規則 7 の根拠。
- **レシピの TO が、着地した時点で既に偽だった** — 判定確定 16:22 → 着地 16:38。FROM は
  sha で自己検証できるが、**TO が「今も言いたいことか」は機械で確かめられない**。鮮度の
  責任は渡した側にある (受け渡しの検査は `handoff-block-integrity`)。
- **「起票が未実施」という記録が、起票の直後まで生き残った** — 規則 8 の実例。
- **issue を PR で代替しない** — PR だけ取得しても、PR を伴わない close・再割当・優先度
  変更は検出できない。取得対象に issue を含める。

## アンチパターン

- 「直近」で窓を濁す / 上位候補がたまたま遅かったときに窓が狭まる順位づけ
- セッション開始時の一括取得で解決したことにする (却下済み — 窓はセッション途中に開く。
  必要なのは提示直前の取得)
- 写しの数値を再掲して as-of だけ新しくする (鮮度のロンダリング)
